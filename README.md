# evitation

ブラウザで動く物理光学シミュレータ集。トップページのメニューから各シミュレータを開く。

**公開ページ: https://atsuhiron.github.io/evitation**

依存は Vite / TypeScript / Vitest のみで、実行時ライブラリは使っていない。

## セットアップ

```bash
npm install
npm run dev
```

| コマンド | 内容 |
| --- | --- |
| `npm run dev` | 開発サーバ (http://localhost:5173) |
| `npm run build` | 型チェック + 本番ビルド (`dist/`) |

| `npm test` | ユニットテスト |

## 収録シミュレータ

### 単色光の色 (`#/monochromatic`)

可視光の波長 (380–780nm) を指定すると、対応する sRGB の色を表示する。

- 波長スライダー / 数値入力
- 色スウォッチと RGB (8bit) / HEX / linear RGB / 視感度 V(λ) の表示(クリックでコピー)
- 明るさの決め方を 2 通りから選択
  - **最大成分正規化**: どの波長も同じ明るさで表示する。色相の比較向き
  - **相対輝度**: 表示輝度を視感度 V(λ) に比例させる。555nm が最も明るく、可視域の両端は暗く沈む
- 可視光スペクトル帯(クリック / ドラッグで波長選択)

### 単色光の合成 (`#/mixture`)

複数の単色光を重ね合わせた光の色を表示する。合成後の三刺激値は各成分の単純な和 `XYZ = Σ Iᵢ·cmf(λᵢ)` になる(グラスマンの法則)。**線形和が成り立つのは XYZ 空間の中だけ**で、波長を平均しても RGB 値を足しても混色の結果にはならない。

ここで足しているのは強度であって振幅ではない。つまり干渉の起きないインコヒーレントな重ね合わせで、同じ「合成」でも干渉とは別物。

- 成分の追加・削除(1〜6 本)、成分ごとの波長と強度
- 強度の基準を 2 通りから選択
  - **放射強度**: `XYZ = Σ I·cmf(λ)`。物理量そのもの。視感度の低い波長は強度を上げてもあまり明るくならない
  - **輝度基準**: I をその成分が担う輝度とみなす(放射強度は `I / ȳ(λ)`)。強度が同じなら同じ明るさに見える。この定義だと合成後の Y がちょうど ΣI になる
- 明るさの決め方(単色光ページと同じ 2 モード)。合成では輝度を積み上げると上限を超えうるので、白飛びした場合は注記が出る
- スペクトル帯に各成分を縦線で表示(高さは強度の比)
- プリセット

プリセットの強度は手で選んだ数値ではなく、目標の色度から解いて求めている(`solveMixIntensities` / `solveTwoLineMix`)。

| プリセット | 見せたいこと |
| --- | --- |
| CIE RGB 三原色 → 白 | 700 / 546 / 436nm の 3 本だけで D65 の白ができる |
| マゼンタ | 450 + 650nm。スペクトル帯のどこにも無い色で、単一の波長では作れない |
| 補色対 → 白 | 491 + 607nm。白色点を挟んで向かい合う 2 波長は、たった 2 本で白になる |
| ナトリウム D 線 | 二重線でも、色としては単色光と区別がつかない |

### 黒体放射 (`#/blackbody`)

温度 T [K] だけで分光分布が決まる理想的な放射体の、スペクトルと色を表示する。分布はプランクの法則

```
B_λ(λ, T) = (2hc²/λ⁵) / (exp(hc/(λkT)) − 1)
```

で与えられる。既存の 2 ページが扱っていたのは δ 関数的な線スペクトルなので、`spectrumToXYZ` による**連続スペクトルの積分を実際に通す初めてのページ**でもある。

- 温度スライダー(1000–20000K)と数値入力
- 色温度帯(クリック / ドラッグで温度選択)
- 色スウォッチと RGB (8bit) / HEX / linear RGB / 発光効率 [lm/W]
- スペクトル図(100–3000nm)。可視域をスペクトル色の帯で示し、ウィーンの変位則が与えるピーク波長を破線で描く
  - **ピーク正規化**: 各温度の曲線を自身のピークで割る。形だけを見るので、ピークが可視域を横切っていく様子を追いやすい
  - **対数目盛(絶対値)**: 分光放射輝度そのもの。曲線が交差せず高温が常に上に来る
- 明るさの決め方(他ページと同じ 2 モード)

**温度を変えても放射の総量が変わらないよう正規化してある**(∫B dλ = 1)。したがって明るさの違いはそのまま「放射のうちどれだけが可視域に落ちるか」の違いを表し、相対輝度モードの明るさは**発光効率 [lm/W] そのもの**になる。∫B̂ dλ = 1 のとき Y は「放射のうち視覚に届く割合」なので、効率は K_m·Y (K_m = 683 lm/W) で求まる。

効率が最大になるのは約 6600K で、それでも 95 lm/W ほど — **理想的な黒体ですら、放射の 86% は目に見えない形で出ていく。** この温度は手で書かず、走査して求めている。

| プリセット | 見せたいこと |
| --- | --- |
| ろうそくの炎 (1850K) | 赤熱の側。放射のほとんどが赤外に落ち、効率は 0.8 lm/W |
| 白熱電球 (2856K) | CIE 標準イルミナント A の定義温度。効率の最大点から大きく外れている |
| 太陽(表面) (5778K) | 有効温度。ピークがちょうど可視域の中央付近に来る |
| 発光効率が最大 (6628K) | 走査で求めた値。95.4 lm/W |
| 青色巨星 (20000K) | ピークは紫外の奥。可視域に届くのは裾だけで、効率はふたたび落ちる |

なお、この形の分布に近いのは白熱電球や星のように**熱で光るもの**だけで、蛍光灯や LED のスペクトルはまったく違う形をしている。

温度軸(スライダーと色温度帯)は温度そのものではなく **1/T について線形**に刻んである。温度で等分すると、色が最も激しく動く 1000–4000K が全体の 16% に潰れてしまうため。色の変化がほぼ 1/T に比例することは、写真の分野で色温度の差をミレッド (10⁶/T) で測る理由でもある。

### 大気によるレイリー散乱 (`#/rayleigh`)

単色光か黒体放射のどちらかを光源に選び、air mass (AM) を与えて、大気を通ったあとの色とスペクトルを表示する。**光が媒質を通って変質する側に入る最初のページ**だが、減衰は波長ごとの掛け算

```
S′(λ) = S(λ) · exp(−τ(λ)·m)
```

にすぎないので、色のパイプライン(`spectrumToXYZ` → `xyzToColor`)は何も変わらない。新しいのは τ(λ) の中身だけ。

- 光源の切替(単色光の波長 / 黒体の温度)
- air mass のスライダーとプリセット
- 減衰前後の 2 つの色スウォッチと、入射光 / 透過光の HEX・RGB (8bit)・輝度の透過率
- スペクトル図(300–1000nm)。透過率 T(λ) の曲線を常に重ねて描く

#### τ(λ) は当てはめ式ではなく断面積から積み上げる

`0.008569 λ⁻⁴(1 + …)` のような当てはめ式で済ませることもできるが、それでは検算のしようがない。σ や ウィーンの b を SI 定義値から導出したのと同じ方針で、分子 1 個の散乱断面積から積み上げている(手順は Bodhaine et al. 1999)。

1. **屈折率** n(λ) — Peck & Reeder (1972) の分散式。550nm で 1.000278
2. **キング補正係数** F(λ) — 空気の分子が球対称でないぶんの補正。550nm で 1.049 と、**4% あるので無視できない**
3. **断面積** σ = 24π³(n²−1)² / (λ⁴N²(n²+2)²) · F(λ)。550nm で 4.51e-27 cm²
4. **カラム密度** N = P·A/(m_air·g)。静水圧平衡そのもので、地表の気圧は真上にある空気の重さに等しい。だから大気の温度分布も高度分布も知らずに、気圧だけから分子数が決まる
5. **光学的厚さ** τ = σ·N。550nm で 0.097

導出すると副産物が出る。**可視域での実効的なべきは 4 ちょうどではなく ≈ 4.08** になる(380nm で 4.18、780nm で 4.04)。λ⁻⁴ をベタ書きしていたら決して出てこない値で、テストで確認している。

| λ | τ | T (AM 1) | T (AM 5) | T (AM 37.9) |
| --- | --- | --- | --- | --- |
| 400nm | 0.360 | 0.698 | 0.166 | 0.000 |
| 550nm | 0.097 | 0.908 | 0.616 | 0.025 |
| 700nm | 0.036 | 0.964 | 0.834 | 0.252 |

#### 減衰前後で明るさのスケールを共有する

`xyzToColor(xyz, 'max')` を前後それぞれに掛けると、両方の最大成分が 1 に揃って**減衰が画面から消える**。単色光にいたっては前後が完全に同じ色になる。そこで既定モードでは、入射光の最大成分が 1 になる係数を求めて**透過光にも同じ値を掛ける**。

同じ係数を掛けるだけで済むのは、相対輝度モードが入力について 1 次同次だから(色域マッピングも輝度の正規化も、入力を k 倍すれば出力が k 倍になる)。依拠しているのは `src/color/` 側の性質なので、テストで固定してある。

太陽 (5778K) を通したときの実測値:

| AM | 透過光 | 輝度の透過率 |
| --- | --- | --- |
| 0(大気圏外) | `#FFF1EA` | 100.0% |
| 1(天頂) | `#F9E6D2` | 90.9% |
| 5(夕方) | `#E4C088` | 62.5% |
| 37.9(地平線) | `#5F2600` | 4.2% |

もうひとつのモード「それぞれ最大成分正規化」は色相の変化だけを比べる。**単色光ではこのとき前後が完全に同じ色になり、それがそのまま「単色光では色は変わらない」という事実の提示になる** — 波長が 1 本しかなければ三刺激値が定数倍されるだけで色度は動かない。色が変わるのは連続スペクトルだからこそ、という対比がこのページのもうひとつの主題。

#### air mass の軸は線形

黒体ページが 1/T の逆数目盛を採ったのとは**逆の判断**で、理由がある。色相のずれは log T(λ₁) − log T(λ₂) = m·(τ(λ₂) − τ(λ₁)) すなわち **m に比例する**ので、線形の軸のままスライダーを動かすと色がほぼ等速で変わっていく。上限 37.9 は Kasten & Young (1989) の式に天頂角 90° を入れて得ている(単純な 1/cos z なら地平線で発散してしまう)。

| プリセット | 見せたいこと |
| --- | --- |
| 大気圏外 (AM 0) | 減衰なしの基準。前後のスウォッチが完全に一致する |
| 天頂 (AM 1) | 最良の条件でも 400nm は 3 割が失われている |
| AM 1.5 | 太陽電池の性能評価に使う標準条件(天頂角 48.2°) |
| 夕方 (AM 5) | 太陽高度 11°。黄から橙へ移りきるあたり |
| 地平線 (AM 37.9) | 青はほぼ完全に消え、可視域の明るさも 1 割を切る |

なお、実際の大気の減光にはエアロゾルとオゾンも効くので、ここで見えるのは**レイリー散乱だけを取り出した理想化**。地平線に近い AM 38 付近では、大気を平行平面とみなす `τ·m` の扱い自体も精度を失う。

ここで失われた光がどこへ行ったのかは、次の「空の色」ページが計算する。2 ページで 1 組になっている。

### 空の色 (`#/sky`)

太陽の黒体温度と高度を与えて、**東の地平線 (−90°) から天頂 (0°) を通って西の地平線 (+90°) まで**の空の色を表示する。レイリー散乱ページが `exp(−τ·m)` で失われる分を扱ったのに対し、こちらはその行き先を計算する。

- 太陽高度のスライダー(0–90°)とプリセット、太陽の温度のスライダー
- 空の色の帯(角度軸。縦線が太陽の位置)
- 代表 3 方向(天頂 / 太陽の方向 / 太陽の反対側)の分光放射輝度と色
- 散乱の次数(単散乱のみ / 多重散乱を含む)の切替

#### 平行平面では東西が対称になってしまう

最初は平行平面で、単散乱が閉じた形で解けていた(`planeParallelRadiance` として残してある):

```
L₁(λ, Ω) = ∫₀^τ F₀·e^(−t·m₀) · P(Θ)/4π · e^(−(τ−t)·m_v) · m_v dt
         = F₀ · P(Θ)/4π · m_v · [e^(−τ m_v) − e^(−τ m₀)] / (m₀ − m_v)
```

きれいに解けるのだが、**東西の地平線が明るさまで厳密に一致してしまう**(実測で比 1.0000)。理由は 2 つ重なっている。

- レイリー位相関数 `P(Θ) = (3/4)(1 + cos²Θ)` は **Θ → 180−Θ で不変**。西の地平線は Θ = h、東は Θ = 180 − h なので、cos²Θ が等しく P も等しい(日没直前の h = 2° でどちらも 1.4991)
- air mass が `|a|` にしか依らない

さらに単散乱では**色相そのものが左右対称**になる(実測 Δx ≈ 1e-16)。`P(Θ)` も `m_v` も波長に依らないスカラーなので、±a の違いはスペクトル全体の定数倍にしかならないため。

前後対称は本物のレイリー散乱の性質で、これは近似ではない。おかしいのは幾何のほうで、**平行平面には地球の影が存在しない** — 太陽が地平線より上にある限り、大気のあらゆる点が照らされてしまう。実際には日没時、東の低空はすでに地球の影の中にある(東から昇る地球影と、その上のビーナスベルトがそれ)。

#### そこで球殻にして地球の影を入れた

`src/physics/atmosphere.ts` が視線に沿って行進し、各点が影に入っていないかを判定する。

**設計の鍵は「光路長は波長に依らない」こと。**密度プロファイルは全波長で共通で、消散係数は `β(λ)·ρ(z)/ρ₀` と書けるので

```
τ_path(λ) = τ_vertical(λ) × (鉛直の柱を 1 としたときの、その光路の柱密度)
```

と分解できる。**幾何は方向ごとに 1 度解けばよく、波長ループには指数関数しか残らない。**柱密度は要するに air mass そのもので、Kasten–Young の経験式が与えていた量を幾何から求め直していることになる。鉛直の総量はレイリー散乱ページが断面積から導出した値をそのまま使い、ここが決めるのは分布の形だけ(等温の指数大気、尺度高さ 8.5km)。

影の判定は単純で、点 P から太陽方向 S へ伸ばした半直線が固体地球に当たるかを見るだけ。最接近点は `t* = −(P·S)` で、それが前方にあり、そのときの中心距離が地球半径を下回れば影の中。

散乱角は球殻でも光路上で一定(視線も太陽方向も固定の直線なので)。だから `Θ = |a − z₀|` はそのまま使える。

結果、**東西の非対称が出るようになった**(単散乱・エアロゾルなし、東西の地平線の輝度比):

| 太陽高度 | 90° | 30° | 10° | 5° | 2° | 0.5° |
| --- | --- | --- | --- | --- | --- | --- |
| 西/東 | 1.000 | 1.006 | 1.057 | 1.201 | 1.784 | 3.516 |

太陽が高いうちは影が大気に届かないのでほぼ 1、沈むにつれて開いていく。**影が原因であることの対偶**として、太陽が高いときの ±60° の比は位相関数の比 1.75 にそのまま一致する(こちらは影ではなく散乱角の違いによるもの)。

#### エアロゾル(Mie 散乱)

チェックボックスで on/off、量は AOD(550nm での光学的厚さ)のスライダーで 0–0.5。レイリーとは性格が正反対:

| | レイリー | エアロゾル |
| --- | --- | --- |
| 位相関数 | 前後対称 (1.5 : 1.5) | **前方 30.6 : 後方 0.078**(390 倍) |
| 波長依存 | λ⁻⁴·⁰⁸ | λ⁻¹·³(Ångström 指数) |
| 尺度高さ | 8.5km | 1.2km |

強い前方散乱を Henyey–Greenstein `P(Θ) = (1 − g²)/(1 + g² − 2g cosΘ)^{3/2}`(g = 0.76)で表す。Mie 理論の厳密解ではなく、前方への偏りだけを 1 つのパラメータで真似た当てはめ式。粒径分布そのものが場所と天候で桁で変わる量なので、観測から決まる経験パラメータで代表させている。

太陽高度 20° で測った効き:

| AOD | 太陽側 (70°) | 反対側 (−70°) | 比 | 天頂の色度 x |
| --- | --- | --- | --- | --- |
| 0(なし) | — | — | 1.26 | 0.253 |
| 0.05 | 明るい | やや暗い | 14.3 | 0.265 |
| 0.1 | `#FFF4DE` | `#353F4E` | 26.3 | 0.275 |
| 0.5 | — | — | 98.8 | 0.318 |

**太陽側だけが強く輝き、反対側はむしろ暗くなる**(増えた消散を後方散乱の足しでは補えない)。同時に空全体が白色点へ寄る — 前に「多重散乱を入れても空は白っぽくならない」と書いた、その白っぽさの主因がこちら。

**単一散乱アルベド ω は 1 とする(吸収しない)。**実際は ω ≈ 0.9 だが、下の収支の厳密性は ω = 1 でしか成り立たないので、強いテストを持てるほうを取った。

#### 薄明(太陽高度 −18° まで)

地球の影を入れたので、太陽が沈んだあとも意味のある計算ができる。上層大気はまだ照らされている。

- 影から出る高度は `R(1/cos|h| − 1)`。h = −1° で 1.0km、−6° で 35km、−12° で 142km(大気の上端 100km を超えるのでほぼ全部が影)
- 日中とは上下が逆転して、**天頂のほうが地平線より明るくなる**。低い視線ほど、影に入った濃い大気を長く通るため
- 日没から 6° 沈むまでに天頂の明るさは 2 桁落ちる

**このモデルの最も弱いところがここ。**多重散乱の見積もりは平行平面の収支に頼っているので、太陽高度が 0 以下では入口が閉じて 0 になる。実際の薄明の明るさは大半が多重散乱なので、暗く出すぎる。薄明の天頂が青ではなく灰色になるのも、オゾンの Chappuis 吸収を入れていないため。

#### 数値上の注意

`m₀ ≈ m_v`(太陽方向とその鏡像)で分母が 0 に近づくので、planck.ts と同じく `expm1` に書き換えてある。**括り出すのは指数の小さいほうでなければならない** — 逆にすると視線が地平線に寄ったとき `e^(−大)` が 0 にアンダーフローする一方 `expm1(+大)` が Infinity になり、`0 × ∞ = NaN` が出る。

エアロゾルを収支に混ぜたとき、**Henyey–Greenstein が μ の偶関数でない**ことに注意が要る。直達光は下へ進むので上向きに散乱される角度は cosΘ の符号が反転する。レイリーの ⟨P⟩ は偶関数なので上下で同じ値になりこの区別が要らなかったが、前方に偏った位相関数で同じ値を使うと上へ抜ける分を過大評価し、**収支の等式が破れる**(実際に破れて気付いた)。加えて、前方に尖った位相関数は 32 点の求積では解ききれないので、離散化した位相関数をその求積の上でちょうど 1 に規格化し直している(離散座標法で使われる標準的な処置)。

#### 多重散乱はエネルギー収支の残差から見積もる

保存散乱 (ω = 1) の平行平面大気では、次が**厳密に成り立つ**:

```
E = E↓₁ + E↑₁ + E₂₊
```

直達光から取り去られたエネルギーはすべて 1 次散乱で生成され、その光は下へ抜けるか、上へ抜けるか、もう一度散乱されるかしかない。したがって残差 `E₂₊` が「2 回以上散乱された光」であり、**構成上つねに 0 以上**になる。近似モデルにありがちな「負になったらクランプ」が要らないのがこの立て方の利点で、この等式自体が位相関数の規格化・上下の閉形式・求積の重みをまとめて検証するテストになる。

置いている仮定は**ひとつだけ** — 2 回以上散乱された光は等方で、上下に半分ずつ抜ける。等方な放射輝度 L が水平面を通す下向きフラックスは πL なので `L_ms = ½E₂₊/π`。

フラックス積分は方位角平均した位相関数 `⟨P⟩(μ, μ₀) = (3/4)[1 + μ²μ₀² + ½(1−μ²)(1−μ₀²)]` を使い、μ について 32 点のガウス・ルジャンドル求積で行う。節点は数表を書き写さず、ルジャンドル多項式の根をニュートン法で解いて求めている(ウィーンの根と同じ理由)。

**この計算だけは平行平面 (1/μ) で行う。**上の等式が厳密に成り立つのはその幾何の中だけだから。代償として太陽高度 0° では `μ₀ = 0` から `E = 0` となり、多重散乱の見積もりも 0 になる — 平行平面では水平面に届く直達光が本当にゼロだからで、実際の薄明の明るさは大気が球殻であることに由来する。このモデルの外側にある。

#### 多重散乱は空を「白っぽく」はしない

実装して測って分かったこと。**2 回以上散乱された光は λ⁻⁴ の重みを重ねて受けているぶん単散乱よりさらに青い**(`E₂₊` は τ の 2 次から立ち上がるので、およそ λ⁻⁸ に近い形をしている)。したがって足すと空はわずかに**青くなる**。

| | 天頂の色度 x (太陽高度 45°) | 多重散乱の寄与 | 地平線/天頂の輝度比 |
| --- | --- | --- | --- |
| 単散乱のみ | 0.246 | 0% | 10.2 |
| 多重散乱を含む | 0.232 | 23.2% | 8.1 |
| (参考) 光学的に薄い極限 τ·F₀ | 0.235 | — | — |

実際の空が計算より白っぽいのは主に**エアロゾル**(ほぼ波長に依らない Mie 散乱)によるもので、これは入れていない。

では多重散乱は何をしているのか。**空の中の非対称を作っている。**単散乱だけだと位相関数は波長に依らない定数倍で、光路長は `|a|` にしか依らないので、**色相が天頂を挟んで完全に左右対称になる**(テストで 12 桁一致を固定してある)。つまり「太陽の近くは白っぽく、反対側は濃い青」という誰でも知っている非対称が出ない。等方な下駄を足すと、単散乱が明るい太陽側では下駄の割合が相対的に小さくなり、下駄は単散乱よりさらに青いので**太陽側のほうが白っぽく残る**。実際の空に見える非対称がこれで現れる。

同時に、暗い方向ほど下駄の効きが大きいので地平線と天頂の差が縮む(10.2 → 8.1)。これも多重散乱が実際に果たしている役割で、CIE の晴天モデルが与える地平線/天頂の輝度比(概ね 3–10)にも近づく。

| プリセット | 見せたいこと |
| --- | --- |
| 正午 (90°) | 太陽が天頂。空は東西対称で、天頂が最も濃い青 |
| 午後 (45°) | 昼間の典型。地球の影はまだ大気に届かず、東西の差は位相関数の分だけ |
| 夕方 (10°) | 太陽の周りが白から黄へ移り始める |
| 日没直前 (2°) | 西が橙、東はもう暗い。地球の影が東の低空を覆い始める |
| 日没 (0°) | ここから下は多重散乱の見積もりが 0 になる |
| 市民薄明 (−6°) | 地上は影の中で、照らされているのは高度 35km より上だけ |
| 天文薄明の終わり (−18°) | 大気の上端まで影に入り、単散乱の寄与はほぼ尽きる |

太陽高度の軸は素直に線形。ただし**色が動くのは地平線の上下 10° に集中する**ので、そこはプリセットで拾う。この偏りを軸で均さないのは、「空は 1 日のほとんど青く、変わるのは最後の数分だけ」という事実そのものだから。

軸が −18° から始まるせいで **0°(地平線)がスライダーの 1/6 という中途半端な位置**に来るので、そこに目盛りを打ってある。つまみは端で半個ぶん内側に寄るため、目盛りの位置は `calc(比 × (100% − 1rem) + 0.5rem)` としている(つまみの実寸は UA のシャドウ DOM の中で読めないので、Chrome の既定 1rem を仮定。ずれても「ずれ量 × |0.5 − 比|」しか効かないので、この位置では 1–2px に収まる)。

明るさは方向ごとではなく**空全体で 1 つのスケール**を掛ける。方向ごとに正規化すると空の中の明暗差が消えて帯がのっぺりする。

#### 計算量

このページだけ計算が重い。帯の 1 標本ごとに球殻を行進し、その各点で分光計算が走る。効いた順に:

1. **幾何を波長ループから出す** — 行進も air mass も散乱角も位相関数も、どれも方向だけで決まる。`samplerFor(方向)` で 1 度だけ解いて閉じ込め、波長ループには指数関数しか残さない
2. **入射スペクトル F₀(λ) と エアロゾルの τ(λ) を状態ごとに表に焼く** — 温度も AOD もモデルの中では固定
3. **レイリーの τ(λ) はパラメータに依存しない** — モジュールの読み込み時に 1 度だけ表にする
4. **視線側と太陽側の柱密度は標本を作る時点で足しておく** — 透過率が 1 本の指数で済み、波長あたりの `Math.exp` が標本 1 つに 1 回になる
5. **影に入った区間は標本から落とす** — 薄明では自然に速くなる(実測 24ms)
6. **三刺激値を描画ごとに覚えておく** — 帯の各標本は「最大値の探索」と「塗り」で 2 回参照されるので、2 度解かない

刻みはどれも「**8bit に落とした色の差が 1 以内**」を基準に、十分細かい基準と突き合わせて決めた。

| | 採用 | 基準 | 誤差 |
| --- | --- | --- | --- |
| 行進(視線 × 太陽) | 96 × 24 | 1536 × 256 | 輝度 0.7%、色差 1 |
| 分光積分 | 380–780nm / 5nm | 360–830nm / 1nm | 色差 1 |
| 帯の標本 | 0.5° 刻み(360 方向) | — | — |

分光積分の 5nm は CIE が等色関数を表にしているのと同じ間隔。10nm まで落としても色差は 1 のままだが、余裕を見て 5nm に留めている。

1 回の再描画はブラウザ実測で **p50 113ms / p90 124ms**(1280×720、帯 878×72px)。内訳はおよそ半分が球殻の行進(波長に依らない幾何)、半分が波長ループ。球殻を入れる前は 3.5ms だったので大きく増えたが、これは幾何の計算がそっくり乗ったぶん。薄明は影で標本が落ちるので逆に速い(24ms)。

削る余地はまだある — 行進の刻み、帯の標本数、分光の刻みがそれぞれ独立した口になっている。

「高度によらない共通スケール」へ初めて切り替えるときだけ、範囲を走査するので 350ms かかる(1 回だけ)。

## 色変換について

`src/color/` が波長と色を繋ぐ部分で、単色光ページ専用ではなく任意の分光分布を扱えるようにしてある(干渉縞や薄膜干渉を実際の色で描くときにそのまま使える)。

処理の流れ:

1. **等色関数** — CIE 1931 2° 標準観測者の x̄(λ), ȳ(λ), z̄(λ) から三刺激値 XYZ を得る。
   単色光は `cmfAt(λ)` を直接、複数の単色光の合成は `spectralLinesToXYZ(lines)`、
   連続スペクトルは `spectrumToXYZ(S)` で積分する(黒体放射とレイリー散乱がこれを使っている)。
   XYZ を入口にした表示用の変換は `xyzToColor(xyz, mode)` で、`wavelengthToColor` はその薄いラッパ
2. **XYZ → linear sRGB** — sRGB (D65) の変換行列を適用する。
   行列は数値をベタ書きせず、規格が定める原色と白色点の色度から導出している
   (`rgbToXyzMatrix`)。出所が追え、テストで検算できる形にするため
3. **色域マッピング** — 下記
4. **正規化** — 上記 2 モードのいずれか
5. **ガンマ** — sRGB の伝達関数を適用して 8bit 化

### 単色光と sRGB 色域について

**単色光は、可視域のほぼ全ての波長で sRGB の色域外にある。** スペクトル軌跡は sRGB の三角形の外側を通るので、XYZ から linear RGB に変換すると必ずと言っていいほど負の成分が出る。つまり画面に出している色は、その波長の光を忠実に再現したものではない。

負の成分は、単純に 0 でクリップすると色相まで動いてしまうため、白を加えて彩度を落とす形で解消している。これは色度図の上で「白色点に向かう直線に沿って、色域の境界に達するまで動かす」操作にあたり、色相の方向を保ったまま色域内へ入れる標準的な手法。どれだけ白を混ぜたかは UI に表示している。

この帰結として、**長波長の赤(620nm 以降)はわずかに赤紫を帯びる。** 例えば 680nm は `#FF0055` 付近になる。これは実装の不備ではなく、その波長の色度が sRGB の赤原色よりも外側かつ下側にあるため、白色点へ向かう直線が色域の赤–青の辺と交わることによる。純粋な赤 (`#FF0000`) にしたければ負の成分を 0 でクリップすればよいが、それは色相を曲げて「らしく見せる」ことになるので採っていない。

### 等色関数データの出典

`src/color/cie1931-data.ts` は生成物で、手で編集しない。CIE 1931 2° 標準観測者の等色関数を 1nm 刻み 360–830nm (471 点) で保持している。

```bash
node scripts/generate-cie1931.mjs
```

データは [colour-science](https://github.com/colour-science/colour) (BSD-3-Clause) のデータセット経由で取得している。値は CIE 由来のもので、一次配布元は cvrl.org (Colour & Vision Research Laboratory, UCL)。

生成スクリプトは書き出す前に、波長が 1nm 刻みで欠けていないこと、ȳ のピークが 555nm でちょうど 1.0 であることを確認する。テスト側でも、等エネルギー白(標準イルミナント E)の色度が x = y = 1/3 になることを検査している — これは ∫x̄ = ∫ȳ = ∫z̄ という等色関数の正規化の定義そのものなので、テーブルのスケール違い・行の欠落・列の入れ替わりを一度に検出できる。

もうひとつの外部基準が黒体放射ページ側にある。**CIE 標準イルミナント A は「2856K のプランク放射体」として定義され、その色度は規格上 (0.44758, 0.40745) と決まっている。** この 1 点を突き合わせることで、プランクの法則・等色関数テーブル・`spectrumToXYZ` の積分をまとめて検証できる。

同じ性格の基準が `src/physics/rayleigh.ts` にもある。**550nm のレイリー散乱断面積 4.51e-27 cm²** は、この分野で最も広く引かれている値(Bodhaine et al. 1999)で、屈折率の分散式・キング補正係数・断面積の式の 3 つを一度に検証できる。光学的厚さ τ(550nm) の文献値には 0.0969–0.0974 の幅があるが、その差はもっぱら重力加速度の取り方から来る(Bodhaine は緯度 45° で大気の質量分布を重みにした実効値 9.7803 m/s²、こちらは SI の標準重力 9.80665 m/s² を使っている。差は 0.27%)。

3 つ目が `src/physics/atmosphere.ts`。等温の指数大気では、**水平方向の柱密度が解析的に √(πR/2H) と分かっている**(R/H = 750 で 34.31)。行進・密度プロファイル・球殻の幾何を一度に突き合わせられる 1 点で、実測 34.33 と 0.05% で一致する。ついでに Kasten–Young の air mass 37.92 とも 10% 以内に収まる — 残る差は屈折と、実際の大気が等温でないことによるもの。

## シミュレータを追加する

1. `src/sims/<id>/index.ts` を作り、`mount(root)` と(必要なら)`unmount()` を export する
2. `src/sims/registry.ts` の `sims` に 1 要素足す

```ts
{
  id: 'double-slit',
  title: 'ヤングの干渉',
  description: '...',
  load: () => import('./double-slit/index.ts'),
}
```

メニューもルーティングもレジストリから組み立てられるので、これ以外に触る場所はない。`load` が動的 `import()` なのは、シミュレータが増えても初期ロードを太らせないため。将来 wasm を使うシミュレータを足しても、そのページを開くまでフェッチされない。

`unmount()` では、DOM の外にぶら下がるもの(`window` のイベント、`ResizeObserver`、`requestAnimationFrame`、タイマー)を解除する。DOM 自体はルータが破棄する。

なお `ResizeObserver` の初回通知は描画ライフサイクルの一部として配られるため、フレームが生成されるまで届かない。canvas の初回描画をこれに任せると空白のままになりうるので、DOM 挿入後に明示的に描画すること(`GradientBar.refresh()` / `SpectrumChart.refresh()` がその例)。

### 共通コンポーネントを作るタイミング

`src/ui/` へ上げるのは **2 人目の利用者が現れてから**にしている。1 人目の時点では何が本質的な引数で何がたまたまの都合なのかが分からず、想像で一般化すると使われない抽象が残るため。

- `spectrum-bar` は単色光ページ専用に作り、合成ページが要るようになった時点で `src/ui/` へ移した
- さらに黒体放射ページで色温度帯が要るようになり、「値 → 色」を外から受け取る `GradientBar` に一般化した。`spectrum-bar.ts` はそれを波長軸で設定するだけの薄いラッパに縮んでいる
- `radio-group` は 3 ページ目で切り出した(それまでは手書きとページ内 private 関数の重複)
- `spectrum-chart` は黒体放射ページ専用として作り、レイリー散乱ページが要るようになった時点で `src/ui/` へ移した。同時に、**プランクの法則を直接呼んでいたところを「曲線をデータとして受け取る」形に一般化**している。広げたのは 2 人目が実際に必要とした範囲(複数曲線・凡例・線スペクトルの縦棒・波長範囲と縦軸の可変)だけ
- `planck.ts` も同じ経緯で `src/physics/` へ上げた。レイリー散乱ページが黒体を光源に選べるようになったため
- `airMassAtZenithAngle` は空の色ページが 2 人目になった時点で `src/physics/air-mass.ts` へ。**軸まわりの定数 (`MAX_AIR_MASS` / `clampAirMass` / スライダーの刻み) は表示側の都合なのでレイリーページに残した** — 昇格するのは共有される部分だけでよい

一般化のしかたにも同じ考え方が効いている。旧 `spectrum-chart` の縦軸には「ピーク正規化」というモードがあったが、これは軸ではなく**データ側の正規化**なので、一般化にあたって外へ出した。図が知っているのは軸の種類(線形か対数か)だけで、割り算は呼び出し側が `valueAt` の中で行う。

共有部品に**足りない口を足す**のも同じ判断で行う。`GradientBar.refresh()` は長らく幅と高さしか見ていなかった — スペクトル帯も色温度帯も、色が状態に依存しない(波長 → 色、温度 → 色 が固定)ためそれで足りていた。空の色の帯は太陽高度と温度で全体の色が変わるので、`recolor()` を足して明示的に無効化できるようにしてある。既存 2 ページは呼ばないので挙動は変わらない。

| ページ | 軸 | 理由 |
| --- | --- | --- |
| 黒体放射 | 温度を **1/T (ミレッド) で線形** | 色の変化がほぼ 1/T に比例する。温度で等分すると 1000–4000K が全体の 16% に潰れる |
| レイリー散乱 | air mass を**線形** | 色相のずれが `m·(τ(λ₂) − τ(λ₁))` すなわち m に比例する。線形のまま色が等速で変わる |
| 空の色 | 太陽高度を**線形**(+ プリセット) | 高度は人が直接目にできる量で、確立した代替尺度もない。色が下 10° に集中する偏りは軸で均さず、プリセットで拾う |
